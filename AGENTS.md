# AGENTS.md

Agent instructions for `jordi.codes` — an SSH-served TUI personal website written in Go.

> **Keep this file up to date.** When you add, rename, or remove interfaces, components, conventions, or patterns, update the relevant sections of this document before finishing your task.

---

## Build & Run

```sh
# Full build: Hugo static site + Go binary (preferred)
make build

# Verify the Go build compiles cleanly (run this after every change)
go build ./...

# Dev mode: rebuild Hugo + run the server locally
make dev
```

Hugo must run **before** `go build` because the Go binary embeds the `public/` directory. The `Makefile` handles this automatically. The `Dockerfile` also runs Hugo before `go build`.

## Core Interfaces (`tui/components/contract.go`)

### `AppContext`
Read-only view of application state. Components receive a pointer (`*tui.Context`) that satisfies this interface — they must **never** type-assert it back to a concrete type.

```go
type AppContext interface {
    Width() int
    Height() int
    SetHelpText(string)
    HelpText() string
    Menu() []cms.MenuEntry
    Subtitle() string
    Now() time.Time
    Contribs() map[string]int
    RemoteAddr() string
    ListLayout() ListLayout
}
```

### `Renderer`
A value type (usually a struct) that draws itself given an `AppContext`.

```go
type Renderer interface {
    Render(AppContext) string
}
```

### `ViewComponent`
A stateful pointer type that can both render and handle messages.

```go
type ViewComponent interface {
    Renderer
    Update(m AppContext, msg tea.Msg) tea.Cmd
}
```

### `ContentSource` (`cms/source.go`)
Pluggable content loading interface. Adding a new source (e.g., database, remote API) requires no changes to `cms/loader.go`.

```go
type ContentSource interface {
    Load(ct ContentType) ([]ContentItem, error)
    LoadBySlug(ct ContentType, slug string) (ContentItem, error)
}
```

Implementations:
- `LocalSource` — loads markdown files from `content/` directories
- `GitHubPinnedSource` — loads pinned repos via GitHub GraphQL API

## Navigation Pattern

  Components **never** mutate the view stack directly. Instead they return a `tea.Cmd` that emits a nav message. `tui.Context.Update()` (in `app.go`) handles the message and calls `pushView` / `popView`.

  | Component wants to…      | Returns                                        | Handled in `app.go` as…      |
  |--------------------------|------------------------------------------------|-------------------------------|
  | Open a content list      | `RequestOpenContentType(entry)` → `OpenContentTypeMsg` | `pushView(NewListView(...))`  |
  | Open a static page       | `RequestOpenStaticPage(entry)` → `OpenStaticPageMsg`   | `pushView(NewStaticDetailView(...))` |
  | Open a detail page       | `RequestOpenDetail(item)` → `OpenDetailMsg`            | `pushView(NewDetailView(...))`|
  | Go back                  | `RequestNavBack()` → `NavBackMsg`              | `popView()`                   |

## Component Conventions

1. **Struct-based Renderers.** Use a struct implementing `Render(AppContext) string`. Do not use free functions for rendering.
2. **Components own their state.** `NewListView`, `NewDetailView`, `NewStaticDetailView` load CMS content in their constructors. They store it internally and never require the caller to pass pre-loaded data.
3. **ViewComponents are pointer receivers.** `MenuView`, `ListView`, `DetailView` implement `ViewComponent` with pointer receivers so they can mutate cursor/scroll state in `Update`.
4. **Renderers are value receivers.** `Footer`, `SectionHeader`, `ErrorView`, `ListBody`, `DetailBody`, `MenuBody` are all value types.
5. **No direct tui/ imports from components/.** The `AppContext` interface in `components` breaks the import cycle — `components` knows nothing about `tui`.
6. **`SetHelpText` is called in `Render`, not `Update`.** Each view sets the footer help text during its own render pass.

## Styling

  All colors and lipgloss styles live in `tui/components/theme.go`. Use the exported/unexported variables from that file rather than defining styles inline. The amber color palette is used throughout. Markdown is rendered with `glamour` using `AmberStyle()`.

## Hugo & Web Output

The website has a raw-HTML web version generated by Hugo as a pre-build step.

- **Config:** `config/hugo.toml` — minimal settings, `params.domain` for the SSH prompt.
- **Templates:** `layouts/_default/` — `baseof.html`, `home.html`, `list.html`, `single.html`. Raw HTML with no CSS.
- **Output:** `public/` — generated by `hugo --config config/hugo.toml --minify`, embedded into the Go binary via `//go:embed public`.
- **Serving:** The HTTP server is inlined in `main.go` as `http.FileServer(http.FS(publicFS))`. There is no separate `web/` package.
- **Single pages** show an SSH shorthand (`ssh <user>@jordi.codes`) derived from the URL path.

## Content Configuration

`config/content.yaml` drives the TUI menu and content types. A `MenuEntry` has:
- `type: content_type` — loads items via `LoadContentItems` from the configured content source (`local` directory or `github_pinned`)
- `type: static` — loads a single Markdown file via `LoadStaticPage`

`content_types` support:
- `source: local` (default) + `folder: ...` for markdown files under `content/`
- `source: github_pinned` to pull pinned repositories for the configured GitHub user (`site.github` or per-type `github_user` override). This requires `GITHUB_TOKEN`.

Content files live under `content/`. Front matter (YAML) provides title and date; the first `#` heading is used as a fallback title.

Hugo sections require an `_index.md` file in each content directory (e.g. `content/recipes/_index.md`). The CMS loader skips `_index.md` files automatically.

Images live in per-section `images/` directories (e.g. `content/recipes/images/`) and are referenced from markdown as `../images/filename.jpg`. The `{width="N"}` attribute syntax on the line after an image controls display width in both Hugo and the TUI.

Shortcode parity:
- Hugo and TUI both support the `projects` shortcode in markdown (`{{< projects user="..." limit="N" >}}`).
- Hugo resolves it via `layouts/shortcodes/projects.html` using `resources.GetRemote`.
- TUI resolves shortcodes directly in `tui/components/markdown.go`.
- Both require `GITHUB_TOKEN` at runtime for GitHub API access.

## What to Avoid

- Do **not** type-assert `AppContext` back to `*tui.Context` inside `components/`.
- Do **not** add new free-function renderers — add a struct implementing `Renderer` instead.
- Do **not** have components push/pop views themselves — emit a nav message and let `app.go` handle it.
- Do **not** import `jordi.codes/tui` from `jordi.codes/tui/components` or `jordi.codes/tui/layout` (circular).
- Do **not** import `jordi.codes/tui/components` from `jordi.codes/tui/layout` (layout is a leaf package).
